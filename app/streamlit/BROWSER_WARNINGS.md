```
Feature Policy: Skipping unsupported feature name "sync-xhr"
Feature Policy: Skipping unsupported feature name "usb"
Feature Policy: Skipping unsupported feature name "vr"
Feature Policy: Skipping unsupported feature name "wake-lock"
Feature Policy: Skipping unsupported feature name "xr-spatial-tracking"
```

**Why they appear:**
- Streamlit renders custom components (like the Cookie Banner and Analytics) in sandboxed iframes.
- Existing Streamlit versions set a broad `allow` attribute on these iframes to ensure maximum compatibility.
- Modern browsers have deprecated or renamed some of these features, so they log a warning when they see the old names.
- This is an external issue between Streamlit and browser vendors.

**Why you cannot fix them (normally):**
- The `allow` attribute is generated by Streamlit's internal code (`IFrameUtil.js`), not our app code.
- Blocking these features is actually correct (we don't need them), so the warning is just informational.

**How to silence them (Optional Fix):**
We have included a patch script that modifies the installed Streamlit library to remove the deprecated feature names causing these warnings.

Run this command if you want to silence them (e.g. after reinstalling requirements):
```powershell
python scripts/patch_streamlit_iframe_policy.py
```
*(Note: I have already run this for you in the current environment.)*

**Impact:** ✅ **None**. These are effectively "Notices" that some features are not available.

## 2. Status: Resolved Warnings

### Theme Color Warnings (Fixed in 1.55.0)

**What you see:**
```
Invalid color passed for widgetBackgroundColor in theme.sidebar: ""
Invalid color passed for widgetBorderColor in theme.sidebar: ""
Invalid color passed for skeletonBackgroundColor in theme.sidebar: ""

or (on newer versions):

"theme.sidebar.widgetBackgroundColor" is not a valid config option
"theme.sidebar.widgetBorderColor" is not a valid config option
"theme.sidebar.skeletonBackgroundColor" is not a valid config option
```

**Why they appear:**
- Theme option support has changed across Streamlit versions
- Some versions emit browser warnings for empty internal sidebar color values
- Newer versions reject unsupported `theme.sidebar.*` keys at startup

**How to handle them safely:**
- Keep only officially supported config keys in `.streamlit/config.toml`
- Do not add unsupported keys such as:
   - `theme.sidebar.widgetBackgroundColor`
   - `theme.sidebar.widgetBorderColor`
   - `theme.sidebar.skeletonBackgroundColor`
- If warnings are repeated in-browser, remove the entire `[theme.sidebar]` block and rely on app CSS for sidebar styling
- If browser-only empty-value warnings appear, treat them as framework noise unless UI is affected

**Impact:** ✅ Usually none - Streamlit falls back to defaults and app displays correctly

## What YOU Can Control

### ✅ Things You Can Do:

1. **Reduce some warnings** by disabling analytics:
   ```python
   # In config.py
   ENABLE_ANALYTICS = False  # Removes Clarity iframe warnings
   ```

2. **Filter console output** in browser DevTools:
   - Chrome/Edge: Console → Filter box → enter `-Feature` to hide Feature Policy warnings
   - Or click "Hide warnings" to remove all warning-level messages

3. **Disable cookie consent banner** (if not needed):
   ```python
   # In config.py  
   ENABLE_COOKIE_CONSENT = False
   ```

### ⚠️ Things You CANNOT Fix:

- Feature Policy warnings (browser security - working as intended)
- Framework-internal empty-value warnings in some Streamlit builds
- Most Streamlit framework messages

### ✅ Theme Config Rule of Thumb

- Use only documented Streamlit theme keys
- After Streamlit upgrades, re-check startup logs for deprecated/invalid options
- If a warning starts with `is not a valid config option`, remove that key from config

## When Should You Worry?

**Investigate ONLY if:**
- ❌ App functionality is actually broken
- ❌ Users report issues (not just console messages)
- ❌ Red ERROR messages appear (not yellow warnings)
- ❌ You need specific blocked features for your use case

**DON'T worry about:**
- ✅ Yellow warning messages (informational)
- ✅ Feature Policy messages (security working correctly)
- ✅ Internal theme empty-value warnings when UI works normally
- ✅ Messages that don't affect user experience
